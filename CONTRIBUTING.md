# Contributing to Whereabouts

Thanks for your interest! The project is pre-alpha and its design is still moving, so please open an issue to discuss before starting on anything substantial.

## Ground rules

- Read [AGENTS.md](AGENTS.md) — it's the project guide for humans and coding agents alike: layout, commands, guardrails and coding conventions.
- Design decisions live in [docs/02-decisions.md](docs/02-decisions.md). If your change needs a new decision, propose it there (status **Proposed**) in your PR.
- Work is organised in stages → waves → sessions ([docs/08-development-workflow.md](docs/08-development-workflow.md)). Outside contributions are welcome as ordinary PRs too.

## Workflow

1. Branch from `develop` (`fix/<topic>`, `docs/<topic>`, …). `main` only receives stage-complete merges.
2. Use [Conventional Commits](https://www.conventionalcommits.org/) with the crate as scope: `fix(readers): handle empty .dbf`.
3. Before opening a PR: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
4. Open the PR against `develop` and fill in the template. PRs are squash-merged.

## Test data

Never attach confidential GIS data to issues or PRs. Corpus files must be synthetic (generated by `tests/corpus/scripts`) or redistributable with their provenance recorded in `tests/corpus/manifest.toml`.
