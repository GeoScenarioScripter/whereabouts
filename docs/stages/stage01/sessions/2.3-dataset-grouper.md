# stage01/2.3 — dataset-grouper
Date: 2026-10-27 · Issue: #7 · PR: see GitHub · Verification reached: V1 (local Windows)

**Context**: depends on 1.1 (core types) and the D-27/D-28 hand-offs. The spec asked for grouping over a directory view, rules per format family, and an incremental API returning a dirty set. Names only; no file contents are read.

## What changed
- `crates/datasets/src/lib.rs` — crate docs and public API: `DirectoryView`, `MemoryTree`, `Entry`, `Grouper`, `GroupDelta`, `is_relevant_name`.
- `src/view.rs` — `DirectoryView` (`for_each_child(dir)`, `entry(frn)`) and `MemoryTree`, an in-memory tree that applies `SourceEvent`s (used by tests and, later, by the pipeline).
- `src/rules.rs` — pure naming rules: case-insensitive stems, multi-dot names (`a.b.shp`), `.shp.xml`, per-format sidecar tables (shapefile, raster, point cloud, lone `.dbf`), GPKG `-wal/-shm/-journal` ignored, FGDB `*.gdb` folder signature (internals never surfaced, nested `.gdb` handled), DWG as `NameOnly`, single-file Tier 1 classification. Anchors get `MemberRole::Main`; sidecars get their role (Shx/Dbf/Prj/Cpg/AuxXml/Ovr/Msk/WorldFile/...).
- `src/fold.rs` — WTF-8 byte case folding for names (D-28), no allocation of lossy strings.
- `src/grouper.rs` — stateful per-volume `Grouper`: `full_scan` (also reconciles after a rescan) and `apply_batch(events)` returning `GroupDelta { added, changed, modified, renamed, removed, moved_dirs }`. Dataset IDs are (volume, anchor FRN) (D-27).
- `crates/datasets/tests/listings.rs` — 47 table-driven messy listings plus id/kind, no-standalone-member, case-sensitive-directory, lone-surrogate, hard-link and 100k-ish large-directory tests.
- `crates/datasets/tests/incremental.rs` — 18 tests: every event type (Created, Deleted, Renamed, Modified, FullRescanRequired), anchor renames without re-extraction, sidecar rename in/out, shared members, FGDB lifecycle, directory events, order independence within a batch, and a seeded random test (batches vs full scan; a deliberate mutation was confirmed caught).
- `crates/datasets/Cargo.toml`, `Cargo.lock` — deps `tracing`, `whereabouts-source`.

## Decisions proposed
- **Events are folded per FRN per batch and are order-independent.** A child may arrive before its parent directory; `Created` for a known FRN is an upsert (covers 2.2's unpaired rename, which arrives as `Created`). — matches what PR #34 (USN source) emits.
- **`GroupDelta.modified` vs `changed`**: `changed` = membership changed (re-extract), `modified` = content change on an existing member (re-extract), `renamed` = anchor renamed/moved only (update the catalog row, no extraction). — gives 3.3 a direct mapping to pipeline actions.
- **Hard-link-only changes are not reported by the source**, so the grouper treats one FRN as one name (the first by sort order); documented and tested not to break invariants.
- **A `Modified` for an unknown relevant file is treated as a missed `Created`**.

## Deviations / contract changes
- None. No frozen core/source types changed. Members use existing `MemberRole` values; the shapefile reader (PR #33) resolves members by `MemberRole` (Shx/Dbf/Prj/Cpg) from an anchor with `Main`, and a lone `.dbf` is `Format::Dbf` with the dbf as anchor, so both agree.

## Follow-ups
- 3.3 (index-pipeline) should call `is_relevant_name` before listing directories, and map `GroupDelta` fields to extraction/catalog actions.
- GPKG layers are not enumerated here (readers produce layers).
- `Grouper` holds a per-volume dataset map in memory; memory at 10M files is not benchmarked (4.3).
- Hard-link names: a second name for the same FRN is not grouped separately; revisit if the source ever reports them.
