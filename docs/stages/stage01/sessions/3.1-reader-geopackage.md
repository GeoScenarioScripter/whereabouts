# stage01/3.1 — reader-geopackage
Date: 2026-11-08 · Issue: #11 · PR: pending · Verification reached: V2 (local Windows; CI pending)

**Context**: consumes the frozen core FormatReader contract, the 2.6 reader/adapter registries and bounded I/O meter, and the committed 1.2 GeoPackage oracle corpus. Implements the stage01/3.1 metadata reader.

## What changed
- `crates/readers/src/gpkg.rs`: GeoPackageReader, registered in `src/lib.rs`. Deterministic layers from gpkg_contents, including features, attributes, tiles and 2d-gridded-coverage. Geometry kind and Z/M come from gpkg_geometry_columns. WKT2 definition_12_063 wins over WKT1; organization/code is preserved as an out-of-band AuthorityCode. Undefined SRS rows yield no CRS.
- `crates/readers/src/gpkg/sqlite.rs`: private, safe, read-only SQLite table-page reader using SourceFile. Supports 512–65536-byte pages, table interior/leaf pages, signed integers, REAL, UTF-8/UTF-16, overflow records and column-level INTEGER PRIMARY KEY rowid aliases. Validates pointers, lengths and cycles. No SQL, native library, locks, writes or journal/sidecar creation.
- Bounds use gpkg_contents, checked against the R-tree shadow node bounds. Missing/stale bounds use the R-tree and report partial. Optional refinement reads only stored geometry envelopes (or Point doubles) to avoid float32 R-tree rounding; general coordinate arrays are never scanned.
- Counts use gpkg_ogr_contents, then R-tree rowid leaf cells, then feature-table leaf cells. The last operation is the count(*) equivalent without reading feature BLOB overflow bodies. Every page/overflow-link read is charged against ReadLimits.max_bytes and traversal checks the per-dataset deadline.
- Active nonempty WAL/rollback journals defer extraction as partial with no layers. The reader checks transaction sidecars before and after, and rereads the SQLite header to detect concurrent changes. A checkpointed database needs only read permission on its file/directory; it never needs directory write permission. Like any lock-free reader it cannot promise a transactional snapshot against arbitrary concurrent rewrites; changed datasets need retry by the pipeline.
- `crates/readers/tests/geopackage.rs`: corpus metering, immutable bytes/mtime/listing tests, active-WAL deferral, a Unix read-only-directory test, budget/mutation tests, count fallbacks, quoted names, UTF-16/overflow/multipage tables, and a 2 MiB geometry whose envelope refinement reads under 64 KiB.
- `tests/oracle/src/adapters/geopackage.rs` and registry entry: Status/Layers/GeometryType/FeatureCount/NativeExtent checks. `baseline.toml` raises the three native per-layer rates to 1.0. The only dependency addition is existing workspace rusqlite as a dev-dependency for temporary SQLite fixtures (D-35); no production dependency added.

## Decisions proposed
- Use native SQLite page reads rather than a SQL connection for GeoPackage metadata. A safe rusqlite connection cannot enforce the frozen physical byte cap; raw reads also avoid SQLite locking and sidecar creation. This parser is deliberately limited to metadata/table b-trees, not a SQL engine.
- Defer a GeoPackage with an active WAL/rollback journal until it is checkpointed/closed, returning partial instead of reading stale base pages or taking a lock. The extraction queue should retry it.
- Limits: at most 64 KiB per metadata record, 1,024 columns, 1,024 layers, and 100,000 traversed rows per table, plus the caller's global byte/time limits. Unsupported WITHOUT ROWID tables, views and unusual SQL definitions retain other metadata and report partial where needed.

## Deviations / contract changes
- No frozen contract changes and no orchestrator-owned docs changed.
- Bounded table-leaf counting replaces literal SQL count(*); the semantics match for rowid tables, with explicit read/time limits and no SQL execution.
- Exact envelope refinement is an additional bounded fallback so stale/missing cases satisfy the oracle's double-precision tolerance despite R-tree float32 storage.
- Corpus already contains all acceptance cases; no corpus/golden files changed. Additional byte-level and container cases are temporary fixtures inside the reader's write scope.
