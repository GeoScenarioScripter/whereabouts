# stage01/2.6 — reader-shapefile
Date: 2026-10-20 · Issue: #10 · PR: (see PR) · Verification reached: V2 (local, Windows; CI for Linux)

**Context**: depends on 1.1 (`FormatReader`, `LayerMetadata`) and 1.2 (corpus, oracle harness). The spec asked for bounded header readers for `.shp`/`.shx`/`.dbf`/`.prj`/`.cpg`, the reader registry that 3.1/3.2 extend, a counting-reader utility, and the shapefile oracle adapter (native fields only).

## What changed
- `crates/readers/src/lib.rs`: the **reader registry** `READERS: &[&dyn FormatReader]`, one line per reader, sorted by name, with a test that no format is claimed twice. Plus `read(&ResolvedDataset, &ReadLimits)` (dispatch; formats without a reader give `ReadError::Unsupported`), `reader_for(Format)`, `readers()`. 3.1/3.2 each add one line.
- `crates/readers/src/io.rs`: `SourceFile` handles all file access. It opens read-only (std share mode, so no locking), reads by seek plus bounded `read_exact`, and charges each read against a per-dataset `Budget` (= `ReadLimits::max_bytes`) **before** reading. The public `measure(|| …) -> (R, IoStats { bytes_read, files_opened, reads })` is the counting-reader utility: a thread-local meter, so it works for any reader that uses `SourceFile` and needs no change to the frozen trait.
- `crates/readers/src/shapefile.rs`: `ShapefileReader`. Per-member reads: `.shp` 100 B, `.shx` 100 B, `.dbf` 32 + 32 per field (at most 1,024 fields), `.cpg` ≤ 64 B, `.prj` ≤ 16 KiB, so **≤ 49,448 B per dataset in the worst case**. How shape types map:
  - PolyLine → `LineString`, Polygon → `Polygon`, as GDAL reports them.
  - MultiPatch → `PolyhedralSurface Z`.
  - Null → no geometry type.
  - Z types report M only when the header's M range is set (neither 0/0 nor ESRI no-data).

  The extent is the header bbox, except that a dataset with no records has none (D-33). Feature count comes from the `.dbf`, falling back to the `.shx`.
- `crates/readers/src/dbf.rs`: DBF header parser (validated header and record lengths, overflow-safe record-count check), OGR field-type mapping (`N`/`F`: decimals → Real, width < 10 → Integer, < 19 → Integer64, else Real; `C`, `D`, `L`; others `Other`), the Clipper wide-`C` width, and `DbfReader` for lone `.dbf` tables (`Format::Dbf`).
- `crates/readers/src/encoding.rs`: `.cpg` label and LDID → `encoding_rs` encoding (GDAL's LDID table; a recognised `.cpg` wins). Undeclared text decodes as UTF-8 when valid, otherwise Windows-1252 (same fallback as `crs`, D-32).
- `crates/readers/src/prj.rs`: decodes the `.prj` (BOM, whitespace and NUL trimmed) and classifies it as WKT2, WKT1, `Wkt1Esri` or PROJJSON. A WKT1 text counts as ESRI when it has no `AUTHORITY` node and uses `"GCS_`/`"D_` names, the same rule as the oracle's `raw_kind`. Nothing is parsed or identified.
- `crates/readers/tests/shapefile_corpus.rs`: bytes-read table over the corpus (< 64 KiB assertion), plus facts the oracle record doesn't compare (fields, CRS kind).
- `tests/oracle/src/adapters.rs`: one `Adapter` line plus `mod native; mod shapefile;`. `adapters/native.rs` holds shared plumbing that 3.1/3.2 can reuse: it builds a `ResolvedDataset` from a manifest case and converts `Result<DatasetMetadata, ReadError>` to a `NativeRecord`. `adapters/shapefile.rs` declares the checks Status, Layers, GeometryType, FeatureCount and NativeExtent.
- `tests/oracle/baseline.toml`: `[format.shapefile.min_rate]` raised to 1.0 for geometry_type, feature_count and native_extent (measured 100%).
- `crates/readers/Cargo.toml`: crate-local `encoding_rs = "0.8.35"` (resolves to 0.8.42); `tempfile` dev-dependency. `Cargo.lock` gains encoding_rs + 5 small transitive crates (all MIT/Apache).

## Decisions proposed
- **Corrupt `.dbf` with an intact `.shp` → `partial`, not `error`**: the geometry type, extent and CRS stay usable, the count falls back to the `.shx` and the fields are dropped. GDAL opens the corpus case `shp_corrupt_bad_dbf` as `ok`. Any `.shp` header problem, including a declared length beyond EOF (truncated records), stays `error`.
- **`.dbf`/`.shx` count disagreement → `partial`, reporting the `.dbf` count** (spec order). GDAL may report the `.shx` count here; the corpus has no such case.
- **Counting reader = thread-local meter (`readers::measure`)**, not a wrapper type. Readers are synchronous and stateless, so a per-thread delta is exactly one dataset. It also gives 4.3 its "bytes read per dataset" figure at no cost.
- **`encoding_rs` for DBF field names and non-UTF-8 `.prj`**: GBK/Big5/Shift-JIS/Windows-125x field names are common in real data. DOS code pages missing from the Encoding Standard (437, 850, 852, …) fall back to UTF-8/Windows-1252.
- **Limits**: `.prj` ≤ 16 KiB (larger → CRS ignored, `partial`), ≤ 1,024 DBF fields (more → list truncated, `partial`).

## Deviations / contract changes
- No frozen contract changed.
- Additions beyond the spec:
  - `DbfReader` for `Format::Dbf` (lone tables), because it reuses the DBF parser.
  - `adapters/native.rs` as a shared adapter helper. The spec's "one adapter line" became one line plus two `mod` lines.
- Acceptance says "corrupt cases → `Error`". `shp_corrupt_bad_dbf` is `partial` instead (see Decisions); the oracle accepts Error or Partial for corrupt cases.
- `ReadLimits::time_budget` is not checked: a dataset costs ≤ 5 opens and ≤ 5 small reads.
