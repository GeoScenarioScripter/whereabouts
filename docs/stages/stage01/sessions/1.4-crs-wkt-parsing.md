# stage01/1.4 — crs-wkt-parsing
Date: 2026-10-19 (review fixes 2026-10-20) · Issue: #4 · PR: #23 · Verification reached: V1 (local Windows + CI Windows/Linux)

**Context**: wave 1 spike, no dependencies. The spec asked for WKT1 / ESRI WKT1 / WKT2 (2015 and 2019) and PROJJSON parsing into a crate-local CRS model with ESRI → canonical name normalisation, ≥ 60 fixtures, and a no-panic guarantee on malformed input. EPSG identification and transforms are 2.4's job; GeoKeys are 3.2's.

## What changed
- `crates/crs/src/lib.rs` — entry points `parse(&str)` (auto-detects PROJJSON vs WKT), `parse_bytes(&[u8])` (BOM strip; valid UTF-8 as is, otherwise Windows-1252 via a built-in table so Latin-1 `.prj` names such as `Réseau` survive; size limit on the raw bytes, decoded text ≤ 3× that), `parse_wkt`, `parse_projjson`; limits `MAX_INPUT_LEN` (256 KiB), `MAX_DEPTH` (32), `MAX_NODES` (16 384).
- `src/model.rs` — `Crs { kind, dialect, name, authority, base, datum, projection, linear_unit, angular_unit, axes, axis_order, components, proj4_extension }`, `CrsKind` (geographic/projected/geocentric/compound/vertical/engineering/unknown), `Dialect` (Wkt1Ogc/Wkt1Esri/Wkt2_2015/Wkt2_2019/ProjJson), `Datum { name, ellipsoid, prime_meridian, to_wgs84, authority }`, `Ellipsoid { a (m), inverse_flattening (0 = sphere) }`, `PrimeMeridian` (always degrees), `Projection { method, method_name, method_authority, parameters }`, `Parameter { name, original_name, value, unit }` with `degrees()`/`metres()`/`normalized()`, `Unit { name, kind, factor }`, `Axis`/`AxisDirection`/`AxisOrder`, `Authority::epsg()`, `Crs::horizontal()`.
- `src/names.rs` (public) — `ProjectionMethod` (37 canonical EPSG-named methods + `Other`, lookup by any OGC/ESRI/EPSG spelling or EPSG method code), `ParamName` (PROJ-semantics canonical names, lookup by spelling or EPSG parameter code), `name_key`/`normalize_name` (strips ESRI `GCS_`/`D_`), `canonical_datum_name` (common datums → EPSG names), `known_unit`. GDAL-style refinement of ambiguous names (ESRI `Lambert_Conformal_Conic` → 1SP/2SP, `Mercator` → A/B, `Stereographic` at ±90° → polar A, OGC `Polar_Stereographic` → A/B, ESRI Krovak with axis flip → North Orientated, WKT1 `Mercator_1SP` + PROJ4 `+a=+b=6378137` extension → Pseudo-Mercator) and parameter harmonisation (PS variant B `latitude_of_origin` → standard parallel; Krovak `azimuth` → co-latitude of cone axis) so every dialect yields the same canonical parameters.
- `src/wkt/tree.rs` — one tokenizer/tree parser for all WKT: `[]`/`()`, case-insensitive keywords, `""` escapes, finite-number check, unquoted ISO 8601 date/time literals (`TIMEEXTENT[2013-01-01,…]`, skipped), depth and node budgets, multiple top-level nodes (ESRI `PROJCS[…],VERTCS[…]`).
- `src/wkt/wkt1.rs` — GEOGCS/PROJCS/GEOCCS/VERT_CS/VERTCS/COMPD_CS/LOCAL_CS/FITTED_CS, TOWGS84, EXTENSION. Unit inheritance as GDAL: angular parameters in the GEOGCS unit, false easting/northing in the PROJCS unit; PRIMEM in degrees.
- `src/wkt/wkt2.rs` — GEODCRS/GEOGCRS/PROJCRS (BASEGEODCRS/BASEGEOGCRS), VERTCRS, ENGCRS, COMPOUNDCRS, BOUNDCRS (Helmert → `to_wgs84`, position-vector and coordinate-frame), DATUM/TRF/ENSEMBLE, generic `UNIT` (2015) resolved by context, derived geographic CRSs (rotated pole) and other `*CRS` → `Unknown`; 2015 vs 2019 detected from 2019-only constructs.
- `src/helmert.rs` — the Helmert/BoundCRS logic shared by WKT2 and PROJJSON (`helmert_from_params`, `apply_to_wgs84`): scale difference decided by its unit (ppm vs unity), unitless abridged WKT2 read as PROJ writes it (`1 + dS`), any malformed/non-finite parameter drops `to_wgs84` and keeps the source CRS.
- Every value × unit-factor product (prime meridian, ellipsoid axes, projection parameters incl. `normalized()`, Helmert terms) is checked finite, so every `Ok(Crs)` is all-finite.
- `src/projjson.rs` — same model from PROJJSON (GeographicCRS/GeodeticCRS/ProjectedCRS/CompoundCRS/VerticalCRS/EngineeringCRS/BoundCRS; `datum_ensemble`; units as strings or objects; `semi_minor_axis`/`radius` ellipsoids).
- `crates/crs/tests/data/` — **246 fixtures**: 57 CRSs × up to 4 encodings (ESRI `.prj`, WKT1, WKT2:2019, PROJJSON) fetched unmodified from spatialreference.org (`fetch.sh`, provenance + EPSG/Esri attribution in `README.md`), 6 hand-converted WKT2:2015 files, 14 hand-written quirk files (incl. USAGE/TIMEEXTENT and a rotated pole in WKT2 + PROJJSON). Families: geographic (10, incl. grads + Paris meridian), geocentric, TM/UTM (9 + south-orientated), LCC 1SP/2SP/Belgium (incl. US survey feet), Albers (4), Mercator/Web Mercator (3), polar stereographic A/B (5), oblique stereographic, LAEA, equidistant cylindrical, Cassini, HOM A/B, Krovak, NZMG, Equal Earth, Mollweide, Robinson, cylindrical equal area, compound, vertical, engineering, bound.
- `crates/crs/tests/fixtures.rs` — table-driven: every fixture → expected kind, method, linear/angular unit, authority, dialect; table ↔ directory consistency; cross-dialect agreement of every shared parameter (degrees/metres, angles mod 360), ellipsoid and prime meridian (359 pairs); spot checks (ftUS, grads, PS-B standard parallel, spheres, TOWGS84 ≡ BOUNDCRS); BOM/CRLF/NUL/pretty-printing variants give identical results.
- `crates/crs/tests/robustness.rs` — every byte-truncation of every fixture (299 384 inputs), 73 800 seeded mutations (byte flips, deletions, duplications, nasty tokens incl. `1e400`/NaN/invalid UTF-8, number replacement), pathological inputs (1M-deep brackets, deep JSON, oversized, 20k siblings, UTF-16, binary), overflowing value × unit-factor pairs (every fixture with unit factors set to 1e307, plus hand-built PRIMEM/ELLIPSOID/PARAMETER/BOUNDCRS cases in WKT1/WKT2/PROJJSON). No panic; every `Ok` result satisfies finiteness/positivity invariants (incl. `to_wgs84` and `Parameter::normalized()`).
- `crates/crs/Cargo.toml` — deps `serde_json`, `thiserror` (both already workspace deps). `Cargo.lock` committed (first session that built locally; see bootstrap follow-up).

## Decisions proposed
- **CRS model is crate-local, raw text stays in core.** `whereabouts_crs::Crs` is the parsed model; 1.1's `CrsDefinition { kind, text }` remains the hand-off from readers. 2.4 wires `CrsDefinition → parse → Crs`. — keeps `core` free of CRS semantics and lets 2.4 iterate on the model without a contract change.
- **Canonical vocabulary = EPSG method names + PROJ parameter semantics.** Methods are named after EPSG (with method codes); parameters collapse to PROJ's `lat_0/lon_0/k_0/x_0/y_0/lat_1/lat_2/alpha/gamma` meanings, with method-dependent renames done at parse time. — 2.4 builds `proj4rs` projections straight from these and matches EPSG by code/name.
- **WKT1 conventions follow GDAL** (PRIMEM in degrees, angular parameters in the GEOGCS unit, GDAL's ESRI method refinements). — the oracle is GDAL; agreeing with its importer avoids spurious mismatches.
- **Input limits**: 256 KiB, nesting 32, 16 384 nodes. Real definitions are < 16 KiB and nest ≤ 8.
- **Helmert scale difference**: decided by the unit (ppm unit → ppm; unity unit → multiplier `1 + dS` or `dS`, whose ranges don't overlap). Without a unit: PROJJSON → ppm; WKT2 `ABRIDGEDTRANSFORMATION` → the multiplier `1 + dS`, because that is how ISO 19162 abridged transformations are written and read by PROJ (`ParameterValue::_exportToWKT` writes `1 + v·1e-6`, `OperationParameterValue::convertFromAbridged` reads `(v − 1)·1e6`). This deviates from the review's "no unit → ppm" for the abridged case only; otherwise every PROJ/GDAL-written BOUNDCRS (e.g. `0.999979511` for OSGB36's −20.489 ppm) would be misread.
- **Unreadable BOUNDCRS transformations are dropped, not fatal** (same as WKT1 `TOWGS84`): the source CRS is what identification and bbox transformation need.

## Deviations / contract changes
- None to frozen contracts (no `core` types used or changed). `whereabouts-core` stays declared as a dependency (from bootstrap) but is unused in this wave.
- Model field names differ slightly from the spec sketch: `ellipsoid { a, inv_f }` → `Ellipsoid { semi_major_axis, inverse_flattening }`, `towgs84` → `to_wgs84: Option<[f64; 7]>`, `projection { method, params }` → `Projection { method, method_name, method_authority, parameters }`; added `dialect`, `base`, `axes`, `components`, `proj4_extension`.

## Follow-ups
- **2.4**: add the EPSG attribution to the root `NOTICE` (outside this session's scope; the fixture README carries it for now) and record the fixture licences alongside the embedded-table decision.
- **2.4**: `Crs::horizontal()` + `Datum::canonical_name()` + `names::normalize_name()` are the intended inputs for name matching; parameter matching should compare `Parameter::normalized()` values with angles mod 360 (ESRI writes the EPSG:3375 azimuth as −36.97°, EPSG as 323.03°).
- **2.4**: decide how to treat WKT1 axis order (`AxisOrder::Unspecified` for WKT1/ESRI without `AXIS`; EPSG:4326 in WKT2/PROJJSON is `NorthEast`). For data in files, GIS order (east/north) is what GDAL assumes.
- Datum-name aliases in `canonical_datum_name` cover the ~10 commonest datums; extend from EPSG/ESRI tables in 2.4 if name matching needs it.
- Robustness test takes ~11 s in debug builds; if CI time matters, gate the full truncation sweep behind `--release` or sample it.
- Out of scope, noted: GeoKeys (3.2); WKT2 `DERIVEDPROJCRS`, derived geographic (rotated pole), temporal/parametric CRSs are parsed only as `Unknown`.
