# stage01/4.1 — query-and-inspect-cli
Date: 2026-11-09 · Issue: #14 · PR: #66 · Verification reached: V2 (V3 pending CI)

**Context**: consumes the frozen nameindex, grouper, catalog and shared 3.3 extraction
contracts. Adds the usable query/inspect commands while preserving `index`.

## What changed
- `crates/query/src/lib.rs`: reusable dedicated rayon search pool; literal case-folded
  names → member FRNs → deduplicated datasets; format/EPSG/R*Tree filters retain
  same-layer semantics and antimeridian splitting. Exact > prefix > substring
  (best member or display stem), newest mtime, then ID; limit applies last.
- Selective terms use indexed member lookups. Broad terms (>256 names and >4×
  candidate datasets) inspect catalog members instead of allocating/ranking or
  executing SQL per non-GIS file. Empty text skips the filename scan. Orphan/cyclic
  anchors and matching orphan members are hidden. No frozen contract changed.
- `crates/cli/src/main.rs`: query loads `<db>.names`, opens the catalog read-only,
  requires one matching checkpoint, and detects catalog commits during query.
  `--snapshot`/`--volume-id` support distinct per-source snapshots. JSON contains full
  dataset/layer records; tables escape controls. CLI index behavior is preserved.
- `crates/cli/src/inspect.rs`: canonical path → bounded sibling/folder directory
  view → grouper → `indexer::extract`; member paths resolve to owning datasets,
  GDB internal paths to the enclosing folder. Discovery stops at 100,000 entries,
  does not follow symlink entries, and readers retain their normal byte/time limits.
  Inspect creates no catalog or dataset sidecars. Default output includes layer
  CRS, native/WGS84 bounds and raster facts. JSON grouping IDs are temporary.
- `crates/cli/README.md`: command semantics, format codes, snapshot handling,
  inspect status/identity conventions and repeatable startup measurement.
- Portable CLI tests: ranking/deduplication, both planner paths, limits, formats,
  antimeridian boxes, same-layer EPSG+bbox, orphan suppression, invalid arguments,
  corrupt/missing/mismatched/ambiguous snapshots; inspect SHP/GPKG/TIFF facts,
  unchanged bytes/mtime/directory entries, malformed contents and GDB internals.
- Existing `index_vhd.rs` now invokes query/inspect processes, compares inspect
  layers/status to indexed metadata, tests member/format/limit/spatial filtering,
  and measures startup to the first dataset row. Existing restart/edit tests remain.
- Dependencies activate existing workspace rayon/serde_json/tempfile entries only.

## Decisions proposed
- CLI rejects mismatched checkpoint state rather than returning mixed results;
  if the catalog advances during query, ask the caller to retry. Multi-source
  ambiguity requires explicit snapshot/volume selection.
- Inspect uses volume 0 and ephemeral discovery IDs in JSON, documented as not
  catalog identities. Reader errors are records with `error` status; command/setup
  failures use nonzero exit. Simple ranking follows the session spec, not Q-17's
  deferred spatial relevance model; Q-11 syntax remains deferred.

## Deviations / contract changes
- None. No core/source/catalog/nameindex contracts or orchestrator documents edited.

## Follow-ups
- Catalog batch member lookup and lightweight ranking columns could avoid loading
  every matching dataset's full layer metadata before applying a limit. Current
  broad queries scale with GIS dataset count; benchmark here has five datasets.
- Snapshot v1 startup rebuilding remains the dominant one-shot CLI cost; a resident
  query service and snapshot v2 are later-stage work. Hard links retain M0's one-name
  limitation. No real-volume Q-18 claim is made from synthetic measurements.
