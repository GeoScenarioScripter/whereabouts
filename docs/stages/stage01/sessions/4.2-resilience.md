# stage01/4.2 — resilience
Date: 2026-11-08 · Issue: #15 · PR: pending · Verification reached: V2 (V3 pending CI)

**Context**: exercises the session 3.3 pipeline and D-36/D-46 restart/retry conventions.
All destructive operations use isolated `TestVolume` VHDs or disposable temp directories.

## What changed
- `crates/indexer/tests/resilience_vhd.rs`: eight elevated scenarios plus a child-process
  worker. A 1 MiB journal wraps through real file churn; a deleted/recreated journal and
  missing-history error recover after reopening. Rescans remove stale catalog rows.
- Restart matrix: corrupt/stale snapshot, catalog checkpoint rollback, missing/corrupt/stale/
  foreign/version-mismatched retry ledger, interrupted ledger temp file. A matching ledger
  with extra retry IDs models death before final ledger shrink and resumes without enumeration.
- Persistence faults: blocked ledger temp creation, SQLite trigger abort at checkpoint update
  (after dataset upserts), and blocked snapshot temp creation after catalog commit. Assertions
  inspect durable checkpoints, unchanged rows, snapshot and ledger before reopening.
- Two child-process kill scenarios: pause inside real NTFS enumeration (new and existing
  catalog), and kill after the ledger is synced while a parent-held SQLite transaction blocks
  catalog commit. Handshake markers and ledger observation replace timing guesses. The parent
  owns the VHD; child guards kill/reap on failure before VHD cleanup.
- A real GeoPackage rollback transaction preserves the complete stored record and leaves one
  durable retry; after rollback/restart, metadata is restored without enumeration. A same-byte
  header write on the disposable copy supplies an anchor event while SQLite buffers pages.
- Own-read check inspects raw USN records for every indexed dataset member across two full
  extractions, before source reason filtering. Catalog/state writes occur off the indexed VHD.
- `crates/indexer/tests/pipeline.rs`: portable transaction-abort regression verifies row and
  checkpoint rollback followed by reopen/replay. Existing workspace `rusqlite` is a test-only
  dependency for fault injection; no new package or production dependency.
- `crates/ntfs/tests/journal_vhd.rs`: real hard-link add/remove/enumerate/last-unlink coverage.

## Deviations / contract changes
- None. Production code, frozen contracts, CLI and CI invocation are unchanged.
- Filesystem failures model persistence interruption boundaries; these tests do not simulate
  hardware power loss or prove filesystem flush guarantees.

## Follow-ups
- M0 hard-link completeness remains explicitly limited: one enumerated name per FRN; adding
  or removing a non-final link emits no source event; final unlink emits `Deleted`. The retained
  name is not guaranteed, and deleting the indexed alias while another survives can leave a
  stale path until rescan. Complete alias tracking is stage02 scope, not silently implemented.
