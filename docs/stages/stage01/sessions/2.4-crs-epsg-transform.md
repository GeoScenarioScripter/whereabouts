## What changed
- `crates/crs/data/epsg.txt` (1.16 MB, generated, committed) — 671 datums, 962 geographic 2D/3D and 5,708 projected EPSG CRSs (incl. deprecated, flagged) with EPSG and Esri aliases and each geographic CRS's most accurate Helmert to WGS 84; values pre-converted to degrees/metres (incl. sexagesimal DMS, grads, US survey feet).
- `crates/crs/scripts/` — `run-in-gdal.sh` (pinned GDAL image, same digest as the corpus), `gen_epsg.py` (proj.db → `epsg.txt`), `g2_fixture_oracle.py` (fixture oracle + `--epsg-sweep`).
- `src/epsg.rs` — lazy (`OnceLock`) table parse, code/name/datum indexes, `Crs` construction from rows; `epsg_crs`, `epsg_name`, `epsg_table_source` in `lib.rs`.
- `src/spec.rs` — `ProjSpec`: any `Crs` (any dialect or the table) → canonical PROJ-style method + parameters + ellipsoid + prime meridian + unit + axis directions + Helmert. Mercator A/B unified as k0, LCC 1SP ≡ 2SP with equal parallels, PS A/B, Hotine B with 90°/90° → `somerc` (as PROJ), angles modulo 360, ESRI `XY_Plane_Rotation` = γ, ESRI `Behrmann`. `equivalent()` (≈ 1 mm tolerances) drives parameter matching.
- `src/identify.rs` — `identify(&Crs) -> Option<Identification { epsg, name, confidence, method }>`: authority (100; also geocentric/vertical citations) → name/alias + equivalent parameters (100) → parameters + datum (70); unknown-datum projected CRSs only if unambiguous; methods without a transform by unique name (90); ties → non-deprecated, 2D; remaining ties → none.
- `src/transform.rs` — `transform_bounds`, `transform_bounds_with(TransformOptions { densify, axis_policy })`, `Transformer` (reusable per CRS, `to_wgs84(x, y)`), `TransformedBounds { extent, partial }`, `TransformError`. Longitudes tracked relative to the central meridian and unwrapped along the ring (Fiji, polar LAEA/stereo across the back meridian); pole inside the box by ring winding, which pole by interior samples; pole on the boundary; Helmert shift (position vector) when the datum has `TOWGS84`/`BOUNDCRS` or the table has one; out-of-domain points dropped → `partial`.
- `src/native.rs` — native inverses where `proj4rs` has none or only a spherical form: Cassini-Soldner, Hotine Oblique Mercator A/B, NZMG, Equal Earth, Robinson, Sinusoidal, ellipsoidal Equidistant Cylindrical (PROJ formulas; validated by the oracle above).
- `src/resolve.rs` — `resolve(&CrsDefinition) -> Resolution { resolved: ResolvedCrs, crs, identification, error }`: bare EPSG codes via the table, WKT/PROJJSON parse + identify, GeoPackage out-of-band authority when the text has none; `geokeys` → `Unparsed` until 3.2.
- `src/model.rs` — `Dialect::EpsgTable`; `src/names.rs` — EPSG method 1111 (TM 3D) → TM, ESRI `Behrmann` alias.
- Tests: `tests/g2.rs` (corpus + fixture report with regression floors; ignored EPSG sweep), `tests/transform_robustness.rs` (every fixture × nasty bounds × 12 parameter/ellipsoid/unit/PM/Helmert mutations, every table CRS: no panic, extents always valid), unit tests per module; `examples/crs_info.rs` (debug tool).
- `crates/crs/Cargo.toml` — `proj4rs = { version = "0.2.1", default-features = false }`; `crates/crs/.gitignore` (sweep output). `NOTICE` — EPSG, Esri and PROJ attribution (#27).

## Decisions proposed
- **EPSG table generated from PROJ's `proj.db` (EPSG v12.029), not the `crs-definitions` crate.** — `crs-definitions` carries proj4/WKT strings only: no Esri aliases (needed to identify `.prj` files by name: 99.9% above), no datum aliases or Helmert parameters, and identification would mean parsing ~6k WKT strings at runtime. The generated table is 1.16 MB of text, parsed once on first use, regenerated by a script in the pinned image. Licence: EPSG terms of use (redistribution with attribution, values converted, not presented as the EPSG Dataset), Esri names Apache-2.0, PROJ MIT — all in `NOTICE`. Bumping the GDAL image bumps EPSG; re-run `gen_epsg.py` and review the diff.
- **`proj4rs` with `default-features = false`.** Its default `aeqd` feature builds C code (`proj4rs-geodesic` + `cc`), which AGENTS.md rules out without a decision. Cost: no Azimuthal Equidistant (7 EPSG CRSs).
- **Native inverses for methods `proj4rs` lacks** (list above) instead of PROJ (D-09 fallback not needed). They are small, pure, bounded, and checked against PROJ; candidates to upstream to `proj4rs`.
- **Axis order for file data = GDAL's traditional GIS order** (`AxisPolicy::TraditionalGis`, default): WKT1/ESRI without `AXIS` → east/north; declared north-first pairs swapped; south-first pairs (classic Krovak, Gusterberg) kept, which matches what GDAL does (measured). `AxisPolicy::Authority` available for authority-ordered sources.
- **Datum shifts**: Helmert only (from the definition, else the EPSG table's most accurate one to WGS 84); no grids (D-09). Within D-33 everywhere measured.
- **Identification confidence scale follows PROJ** (100 authority/name, 70 parameters) plus 90 for name-only matches on methods we can't transform; ambiguity → unidentified, never a guess.
- **Q-14 targets** (for 4.3's `baseline.toml`): `epsg` 0.98, `wgs84_extent` 0.98.

## Deviations / contract changes
- No frozen contract changed (core untouched). Additions to the crate-local `whereabouts-crs` API only: `Dialect::EpsgTable` (new variant of a crate-local enum).
- Spec said `identify → Option<(epsg, confidence)>`; it returns `Option<Identification>` (code, name, confidence, method). `transform_bounds` returns `Result<TransformedBounds, TransformError>` (extent + partial reason) rather than a bare `Wgs84Extent`.
- `proj4rs` is a crate-local dependency (only `crs` uses it). The root `[workspace.dependencies] proj4rs = "0.2.1"` entry (from bootstrap, default features) is now unused — I did not edit it (shared file).
