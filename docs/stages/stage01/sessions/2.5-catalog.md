# stage01/2.5 — catalog
Date: 2026-10-21 · Issue: #9 · PR: (see PR) · Verification reached: V1 (local Windows; Linux via CI)

**Context**: depends on 1.1 (core contracts). Builds the SQLite (WAL) + R*Tree catalog per `03-architecture.md` §4, adapted to the frozen core types. Includes the wave-1 hand-off schema delta, migrations, the write and query API, and a 100k-dataset benchmark.

## What changed
- `crates/catalog/src/lib.rs`: `Catalog` (`open`, `open_read_only`, `transaction`, `write`) and `CatalogTx` (writes plus the same reads; it sees its own writes). The crate doc covers the model and durability.
- `src/schema.rs`: schema v1 and the `PRAGMA user_version` migration runner (append-only list; refuses newer versions). `SCHEMA_VERSION`.
- `src/write.rs`: `register_volume`, `set_checkpoint`/`clear_checkpoint`, `delete_volume`, `upsert_dataset` (runs `DatasetRecord::validate()` first), `delete_dataset`, `set_status`, `rename_dataset`. CRS rows are de-duplicated and pruned when unused.
- `src/read.rs`: `get_dataset` (exact round trip), `datasets_with_member`, `dataset_ids`, `pending_datasets` (most recent mtime first), `find_datasets(DatasetFilter { volume, formats, epsg, bbox, limit })`, `volumes`/`volume`/`find_volume`, `checkpoint`, `stats`.
- `src/convert.rs`: FRN `u64` ↔ `i64` bit-cast, range-checked integer conversions, and a stable FNV-1a CRS definition hash. `src/error.rs`: `CatalogError`.
- `tests/catalog.rs`: 24 integration tests on temp DBs. `examples/bulk_insert.rs`: the benchmark.
- `Cargo.toml`: `rusqlite` (workspace, `bundled`), `serde_json` (+ `float_roundtrip`), `thiserror`, `tracing`, `whereabouts-source`; dev: `tempfile`. All were already workspace entries, so the root `Cargo.toml` is unchanged. `Cargo.lock` gained `rusqlite`/`libsqlite3-sys`/`cc` and their dependencies.

## Decisions proposed
- **SQLite is built from source (`rusqlite` `bundled`).** `libsqlite3-sys` compiles the SQLite amalgamation (3.53.2, `SQLITE_ENABLE_RTREE`) with `cc`. This is a C build dependency. D-10 picked SQLite via `rusqlite`, and the root `Cargo.toml` has had `features = ["bundled"]` since bootstrap, but no decision says so explicitly. Proposal: extend D-10 to accept the bundled SQLite build as the one sanctioned C dependency. The reasons: the SQLite version and R*Tree support are the same on every platform, and Windows has no system SQLite to link against. The MSVC/gcc toolchain is already required. I did not pick a different store.
- **R*Tree row ids encode the layer: `id = layer_id * 4 + part`, at most 4 parts per layer.** The delete trigger and the extent read-back are rowid lookups (`EXPLAIN QUERY PLAN` shows strategy 1, which a test asserts), so nothing is scanned. An extent with more than 4 parts is stored as the union of its parts, with a `warn`. That is a superset, so it is still correct for a coarse filter. `transform_bounds` produces at most 2 parts.
- **Exact bbox test inside SQL.** R*Tree coordinates are f32 values rounded outwards. Auxiliary `west/south/east/north` columns keep the exact f64 values. Each query part probes the R*Tree and then compares the exact values, so edges are exact to the ulp (tested). A query box that crosses the antimeridian becomes a `UNION` of one probe per part, not an `OR`, because an `OR` defeats the R*Tree index.
- **A CRS resolution belongs to its definition, and the latest write wins.** `crs` rows are keyed on (kind, text, authority) through a stable FNV-1a hash plus a full compare. Re-extracting with better identification therefore upgrades every layer that shares the definition. `std::hash` isn't stable across Rust releases, which is why the hash is FNV-1a.
- **`epsg` and `bbox` in `DatasetFilter` must hold for the same layer.** For example, a GPKG with a 3857 layer in Europe does not match "3857 near Wellington".
- **`set_status` keeps stored records valid.** `pending`/`unsupported`/`error` drop the dataset's layers, because they must not carry layers under `DatasetRecord::validate`. `extracted_at` is required except for `pending`.
- **`synchronous = NORMAL` (WAL).** Commits stay atomic and consistent, but the last commits can be lost on power failure. The plan already reconciles a catalog/snapshot checkpoint mismatch (3.3/4.2).
- **Non-finite raster floats are stored as absent.** SQLite turns NaN into NULL, and JSON has no NaN. A non-finite `res_x`/`res_y` reads back `None`, and a geotransform with any non-finite element reads back `None`. Out-of-range integers (`u64` above `i64::MAX`) are an `OutOfRange` error.

## Deviations / contract changes
- No contract changes. Core and source are only consumed. The catalog depends on `whereabouts-source` for `SourceIdentity`/`Checkpoint`.
- The benchmark is an `examples/` binary, not a criterion bench, to avoid adding a new dependency to the root `Cargo.toml` in parallel with 2.1. It can move to criterion once 2.1 adds it.
- Members read back in insertion order, and layers by ordinal, so `get_dataset` returns exactly the record that was upserted (tested), except for the more-than-4-parts union.

## Follow-ups
- **Re-upsert costs about 2× a first insert** (15.5 s vs 7.9 s per 100k), because it replaces members, layers and extents wholesale. 3.3's full-rescan reconciliation could skip unchanged records, or the catalog could diff. Measure in 4.3 before optimising.
- **Planner statistics.** Without `ANALYZE`, SQLite chose a bad plan for the member lookup: 26.8 ms at 100k datasets. I fixed it with `CROSS JOIN`, which brought it to 12 µs, and a plan test guards it. Consider `PRAGMA optimize` on close or periodically (3.3/4.3).
- **4.1:** a batch variant of `datasets_with_member` for many name-index hits at once, and possibly `find_datasets` restricted to a candidate set. Build query boxes with `Wgs84Extent::from_west_south_east_north`.
- **Core (owner of `whereabouts-core`):** `LayerRecord::validate` could reject non-finite `RasterInfo` floats, so the catalog never has to drop them.
- **Orchestrator:** fold the schema delta above into `03-architecture.md` §4 and record the D-10 bundled-SQLite clarification.
- `cargo deny check` was not run locally (not installed); CI runs it. New crates: `rusqlite` and `libsqlite3-sys` (MIT), `cc` (MIT/Apache-2.0), plus `hashlink`, `fallible-iterator`, `fallible-streaming-iterator` and similar.

  - rollback of a failed batch, including the checkpoint;
  - unknown volume and out-of-range values; CRS de-duplication and resolution upgrade;
  - layers without a CRS and with an unparsed CRS; a raster round trip with bit-exact floats, and NaN handling;
  - the more-than-4-parts union; bbox queries over antimeridian parts and with antimeridian-crossing query boxes;
