# stage01/3.2 — reader-geotiff
Date: 2026-11-08 · Issue: #12 · PR: see PR · Verification reached: V2 (local Windows; CI pending)

**Context**: consumes 2.6's reader registry, bounded `SourceFile` and oracle adapter pattern,
and 2.4's CRS model/EPSG table. Implements metadata-only TIFF/BigTIFF and GeoKey decoding.

## What changed
- `crates/readers/src/tiff.rs`: `TiffReader`, registered in `readers/src/lib.rs`. Classic TIFF
  and BigTIFF in both byte orders; dimensions, samples, bits, sample format, compression,
  GeoTIFF affine/GeoKeys, GDAL nodata and XML metadata tags. Never follows imagery offsets.
- Native extent uses all four pixel corners. PixelIsPoint shifts the internal affine by half
  a pixel. PAM overrides internal CRS/affine independently; internal precedes world files;
  world-file centres become pixel corners and supplied `.prj` supplies the fallback CRS.
  This follows [GDAL's documented precedence](https://gdal.org/en/stable/drivers/raster/gtiff.html#georeferencing)
  and [RFC 33](https://gdal.org/en/stable/development/rfc/rfc33_gtiff_pixelispoint.html).
- Linked IFDs and SubIFDs count reduced-resolution images, excluding masks; supplied `.ovr`
  contributes its first image and reduced-resolution descendants. Traversal rejects cycles.
- Byte limits: at most **1 MiB per dataset**, further restricted by `ReadLimits::max_bytes`;
  **64 KiB per metadata block/sidecar**, **1,024 entries per IFD**, **64 IFDs per file**.
  Directory traversal checks the time budget. Broken optional sidecars/overview chains keep
  usable base facts and add partial reasons. Impossible file ranges are malformed data.
- `crates/crs/src/geokeys.rs` (public module): raw GeoKey JSON → `Crs`, plus
  `geokeys::resolve(text) -> Resolution`. Direct projected/geographic EPSG codes and
  user-defined projection parameters, datum/ellipsoid, linear/angular units and prime meridian.
  Unsupported methods/units remain unparsed instead of being guessed.
- `tests/oracle/src/adapters/geotiff.rs`: status, layers, extent, full band type/nodata,
  raster dimensions/resolution and EPSG checks. TIFF-specific integration checks affine and
  overview facts that the generic oracle record does not compare. Baselines raised to 1.0.
- Dependencies: `roxmltree` 0.21.2 (pure Rust, MIT OR Apache-2.0) parses bounded PAM/GDAL XML;
  default parsing rejects DTDs and does not load external entities. Existing workspace
  `serde_json` encodes raw GeoKeys; oracle dev-dep `whereabouts-datasets` checks grouping.

## Decisions proposed
- **Raw GeoKeys representation**: `CrsDefinitionKind::GeoKeys.text` is JSON with the complete
  `directory` SHORT array, `doubles` array, and `ascii` string including any trailing NUL.
  Raw keys remain available for later interpretation; the reader never identifies/transforms CRS.
- **Bounded TIFF metadata**: limits above; larger metadata returns Error/Partial rather than
  reading imagery or following an unbounded IFD chain.

## Deviations / contract changes
- No frozen contracts changed; no corpus/golden or orchestrator-owned documents edited.
- The write scope allows only `crs/src/geokeys.rs` and its module declaration. Existing
  `crs::resolve` has an explicit GeoKeys → Unparsed arm in out-of-scope `resolve.rs`.
  Permission to route that arm was requested but not received. The scope-safe public
  `geokeys::resolve` provides the full resolution result; the oracle uses it directly.
- Compression/GDAL_METADATA are parsed/validated; the frozen core has no fields for generic
  XML metadata or compression, so these are not added to `RasterInfo`.
